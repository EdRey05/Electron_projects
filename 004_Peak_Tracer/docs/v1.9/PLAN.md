## User assessment and scope

The user opened v1.8 in both SnapGene and Geneious and confirmed a useful improvement over Seq7/v1.7. Remaining observations are: some good peaks are too spiky; weaker regions improve little; inherited confidence declines around 600+ bases while PeakTrace remains high much farther; additional tail length beyond about 1–1.1 kb is often unusable. This confirms basic viewer opening and visible signal changes, but is not an exhaustive clear-range/export compatibility test.

Prioritize smoother, better separated supported peaks within the existing read. Do not optimize total read length or manufacture a cyan QV profile. Nucleics distinguishes its basecaller from cosmetic smoothing and uses raw signal for calling; matching its confidence requires a validated caller, not a display adjustment. [Option descriptions](https://www.nucleics.com/peaktrace-online-pro-help/), [basecaller FAQ](https://www.nucleics.com/peaktrace/peaktrace-FAQ.html).

## Implementation sequence and gates

1. **Freeze and identify the baseline.** Record v1.8 commit and hashes of the existing 146 v1.8 AB1 files. Use the same Seq7 inputs and PeakTrace comparators. Save new output as `v1.9_validation/sample4/6-v1.9` and an equivalent sample5 folder. Source inputs and previous outputs must remain unchanged.
2. **Prototype a finite-width resolution model.** v1.8's relative blur removal can leave narrow, angular crests. Separate latent signal recovery from a controlled finite-width output: stronger bounded inverse restoration, then common Gaussian reconvolution. Test a small declared set of inverse strengths/output widths on a deterministic sample4 development subset. This is an approximate signal model, not reconstruction of the proprietary PeakTrace pipeline. Compare against v1.8, and reject candidates whose smoother appearance merely merges the peaks again.
3. **Regularize with measured noise.** Estimate local noise and restrain inverse updates where measured evidence cannot support them. Use a common noise treatment across channels and retain weak/minor-channel evidence. Do not use PeakTrace QVs, a target sequence, or idealized peaks synthesized from PBAS to generate output. Preserve an explicit legacy v1.8 resolver option for controlled ablations.
4. **Evaluate by input-quality region.** Report repeated-base separation and crest shape in Q3–9, Q10–19, Q20–39 and Q40+ regions on fixed input coordinates. Include 600–900-base and later regions. Use an upper-peak width measure for spikiness, plus synthetic true/false crest counts; do not reward deeper valleys alone. Select on sample4 only, then run sample5 without retuning. Both plates were previously seen, so call this replication, not blinded biological validation.
5. **Investigate the quality gap as a separate diagnostic.** Implement and test a base-aware raw-to-analyzed anchor mapping if the signal experiments leave scope for it. Use high-confidence KB anchors, monotone coordinates and held-out anchor prediction errors; reject unsupported mapping or extrapolation. This diagnostic must not change sequence/QVs or claim a new caller. Record explicitly if it remains deferred or fails its gate.
6. **Keep the call/export contract stable.** No default substitutions, insertions, QV increases or new tail calls. Preserve the v1.8 weak-call N policy, duplicate-coordinate repair, raw tags, clear range and synchronized exports. Experimental low-quality substitutions remain off unless independent evidence justifies changing that decision; comparator agreement alone is insufficient.
7. **Validate and document.** Test flat signal, isolated peaks, repeated peaks, measured noise, inaccurate spacing anchors, short reads, FWO permutations and negative flags. Run both real plates, independently audit the written AB1s, and draw comparison plots from saved files. Report tuning trials, rejected approaches, regression counts, limitations and a plan-to-outcome table. Commit coherent stages and write the report beside the task wiki as well as in repository docs.
